# 项目原则与路线

最终希望用户描述一种魔法，经过少量确认和调整，得到美观、能读回、可以保存并继续修改的法阵。当前 0.9.0 公测版已提供[网页版星辰工作室](https://jizhishiroppu.github.io/Asterweave-public/try/)，继续以本地软件优先、普通网站并行推进。

## 四层分工

| 层 | 回答什么 |
| --- | --- |
| 含义层 | 法术说了什么：定义、动作、角色与成员。 |
| 记法层 | 每种含义用什么图形写，怎样从图中读回。 |
| 布局层 | 放在哪里、多大、怎样展开，怎样在保留含义的前提下调整。 |
| 字形层 | 每个符文长什么样；七星投影是当前方案之一。 |

写出：含义 → 记法 → 结构 → 排布 → 画面。读回沿反方向进行，并借助词表识字。有损字形不能反推出任意原文。

## 设计约束

- 有含义的元素必须登记规则；装饰也要明确登记为装饰。
- 每条记法写清楚有含义的属性、可自由调整的属性，以及读回方法。
- 同一画面不能产生未处理的结构歧义；布局不能偷偷改变含义。
- 同一含义、记法、参数和版本应复现同一结果。用过的规则与已保存作品保留版本。
- 美感由具体画面判断，不用元素数量或自动评分代替判断。

| 阶段 | 进展与边界 |
| --- | --- |
| A—B：规格与第一次往返 | 已建立主干，基础生成与读回实验完成。 |
| C—D：规则与紧凑布局 | 已做控制结构、属性匹配与代表性法术的往返验证；复杂布局仍有空散、拥挤和深层过小的问题。 |

现阶段主要改进完整创作过程、模型拆解质量、复杂画面的可读性和局部修改体验。斜视展开服务于观察现有结构；当前配色、光晕与自转只作装饰，不增加法术含义。

## 怎样参与下一步

挑一个实际样例，指出遮挡、留白、文字密度或操作上的具体问题，给出保留原含义的改法。新记法要先写条目、配图讨论，由维护者确认；不把临时试验自动当作既定规则。

自然语言入口把意图整理成明确内容，再由核心检查。模型可能误解描述；成功调用不代替检查结构和画面。复现依据是最终保存的内容与版本，而不是重新请求模型。九个内置函数与用户库已有首版，更多元件关系、复杂布局和完整创作体验继续打磨，不承诺排期。
